## 1. 接入目标与当前结论

本地模式直接 import Core 项目的 `iris_memory_core`，在 AstrBot 已有进程和事件循环中运行；无需 HTTP 服务、端口、sidecar 或 Docker。远程模式使用独立发行的 `iris-memory-sdk` / `iris_memory_sdk` 调用独立 Core 服务。两种入口复用同一份记忆业务实现。

本插件不发行 Python 包，不携带 Core/SDK 源码。Pages、插件配置、人格编辑与绑定、模块开关、Prompt 组装、平台身份适配和实际发送由插件负责，不能要求 Core 实现 AstrBot 专属功能。

**原核查结论（已被后续开发快照更新）：可以开始远程基础功能开发，但不能完成本地内嵌接入。** 当时 Core 的公开边界以 SDK/HTTP 为业务入口，没有冻结的进程内业务 API；该范围决策现已由 Core 的公共 Embedded 接缝落实。

核查基线为 Core `0.13.0` / Schema `20` / 业务契约 `1.11.0`、Python SDK `0.11.1`；源码为 `e2a6bbd7793f7bd4b73a51d32149eb8e3015ed33` 加当时 W01 工作区改动。以下是开发快照，不能仅凭相同版本号认定后续安装物相同。

优先级按插件接入影响定义，与 Core 自己的完整发布门禁分别管理：

- **P0：** 阻塞本地模式，必须先明确接口和责任范围。
- **P1：** 对应功能正式可用前必须补齐或验证；不阻塞其他插件模块开发。
- **P2：** 按插件实际需要或正式发布阶段验收，不能把所有 Console 功能设为 Pages 开发前提。

## 4. P0：本地接入前置

### G-01 公共进程内业务 API

- [ ] 先确认 Core 支持“进程内公共业务调用”的范围，更新公共接口说明与 ADR；保留内部存储、索引、队列的私有边界。
- [ ] 提供稳定导入路径、配置、请求/结果、错误类型和能力声明。最低闭环覆盖观察、显式记忆、Recall、纠正、遗忘；其余按已有能力逐项开放。
- [ ] 内嵌调用与 HTTP 调用复用应用服务和领域规则，不维护第二套记忆引擎，不通过路由函数或 localhost 实现内嵌。
- [ ] Scope、用途、权限、幂等、Expected Revision、删除优先和 Required Lease 在本地入口同样生效；需要可信本地初始化时，提供明确的公共机制，不能让插件拼造内部 AccessContext 绕过验证。
- [ ] 明确同进程信任边界：公共 API 封装不是 Python 安全沙箱；不能将独立 OS 身份隔离承诺原样用于内嵌模式。

**验收：** 从已安装 Core wheel 导入公共入口，仅给临时持久目录和测试 Provider，无监听端口地完成写入→召回→纠正→遗忘→重启保持；业务消费代码不访问私有对象或数据库。

### G-02 生命周期、后台任务与资源所有权

- [ ] 构造与异步启动分开；import/构造不迁移数据库、不创建后台任务、不连接模型。
- [ ] 在现有事件循环中提供明确的启动/关闭语义，支持重复操作、启动失败清理和有界停止；不在 Runtime 内运行或关闭宿主事件循环。
- [ ] 区分自有资源与宿主共享资源；关闭不销毁注入的共享 Provider。任务、缓存、连接、订阅归属明确，无进程级可变单例。
- [ ] 两个不同数据目录的实例互不串数据；同一目录的重复写主或后台维护有检测/保护，不把线程锁当成跨进程保护。
- [ ] 后台加工可以关闭或暂停；重配置不默认同时加载两份大索引。退出时写入结果未知、处理中和未提交任务可诊断。

**验收：** 已有事件循环中反复创建/启动/关闭 50 次，覆盖各启动步骤失败；无重复 Worker、活引用/句柄持续增长，宿主共享资源仍可用。一次 RSS 未下降不能单独证明泄漏，需同时检查资源归属与重复运行趋势。

### G-03 宿主 Provider 注入

- [ ] 复用 Core 现有 Provider 抽象，形成可供公共入口接受的 LLM/Embedding 契约，不再增加一套重复接口。
- [ ] 定义异步等待、阻塞适配、超时、取消、并发与异常规则，不能把明显阻塞工作直接放进 AstrBot 事件循环。
- [ ] 本地允许插件适配宿主模型；远程继续由服务端选择 Provider。Core 类型和依赖不包含 AstrBot 对象，不自动复制宿主密钥或增加服务端回调宿主机制。
- [ ] 明确模型/向量空间指纹及变更规则；不同维度或模型的旧索引不得直接复用。

**验收：** 用不依赖 AstrBot 的异步 Fake Provider 完成公共入口闭环；覆盖慢请求、取消、错误与共享资源所有权。AstrBot 适配器由插件独立验证，不打入 Core 包。

## 5. P1：功能可用性与插件运行要求

### G-04 真实 Embedding 全链路（W05）

- [ ] 把真实 Provider 的配置/密钥引用接到 Worker 建索引和 API 查询，复用现有 HTTP Embedding 适配器及 W01 装配。
- [ ] 支持探测、激活、回滚和模型空间切换；新索引就绪前保持旧模型/旧代一致，不混用空间。
- [ ] 未配置、暂不可用、索引未就绪和成功无命中可区分；确定性测试 Provider 只能显式用于开发。

**验收：** 独立服务从公开部署配置启用真实 Embedding，写入后可语义召回；断网、维度不符、重建失败与切换恢复不破坏现有数据。真实模型验收与 Fake 测试分开记录。

### G-05 真实认知 Provider 与低成本加工（W06）

- [ ] 提供可配置的真实认知模型适配器，接通声明支持的摘要、提炼等能力，替换当前生产装配中的确定性桩。
- [ ] 未配置的能力明确关闭；不以恒定/空候选的成功响应冒充加工完成。
- [ ] 复用超时、并发、重试、熔断和预算治理；支持关闭自动加工、合并重复工作，页面查询/健康检查不能触发模型调用。
- [ ] 模型结果只产生候选，提交仍校验来源、当前修订、权限与策略；不在 SQLite 写事务内等待模型。

**验收：** 固定标注样本证明确实发生摘要/提取且达到预先定义的质量门槛；429/超时/无效输出、来源删除和预算耗尽可恢复。记录调用数、Token 与耗时，不只验 HTTP 200。

### G-06 轻量依赖与小内存运行

- [ ] 给出低负载运行方案：保留 SQLite，向量/图谱及高成本后台加工按能力和配置初始化，不因 import 加载整个引擎。
- [ ] 评估将内嵌运行不需要的服务依赖拆为 Core 自己的可选依赖组；当前 Core 基础依赖包含 FAISS/NumPy/FastAPI/Uvicorn，不能宣称已经完成轻量内嵌依赖拆分。extras 命名由 Core 决定，SDK 始终独立。
- [ ] 索引、缓存、队列、批次和并发有容量上限、清理规则及观测值；明确向量规模增长与重建峰值。
- [ ] 冻结代表性数据规模下的冷启动、稳态、峰值、关闭/重启趋势与后台空闲成本；分别报告插件、Core 和宿主总量。

**验收：** 提供可复现的内存/延迟/调用预算报告，覆盖无模型配置、关闭后台、启用向量与索引重建。插件指南中的 32/64 MiB 是插件增量初始目标，不能直接当作 Core 已达到或必须套用的整体上限。

### G-07 独立 SDK 的生命周期、错误与方法覆盖

- [ ] 为严格热停提供真正异步、可限制在途请求的传输及明确关闭语义；支持连接复用或等价有界资源管理。若借用调用方传输实例，必须说明所有权。
- [ ] 区分 socket 超时、整次调用 deadline、外层协程取消和底层请求结束；当前 `urllib + asyncio.to_thread` 不能通过取消外层协程停止底层请求。
- [ ] 统一可消费的传输/认证/校验/业务/服务不可用错误，保留请求 ID；写入超时保留“结果未知”，有幂等保证才按原键对账/重试。
- [ ] 补齐插件所需且 Core 已公开的客户端方法：例如 Entity Profile，以及 `negotiate` 的 `required_capabilities` 参数。现有 SDK 不支持的 `/console/v1` 不视为自动开放。
- [ ] SSE 仅在确有 Core 事件订阅需求时加入；有界轮询可满足首版时不把 SSE 设为全部开发的前置。

**验收：** SDK-only 干净环境仍无需 Core 或向量引擎；真实 HTTP 慢响应/断开/取消/关闭、并发上限和未知写入通过。停止时不能留下无上限的线程或重试。方法存在、权限与服务实际支持均须验证。

### G-08 插件人格镜像与管理授权

这不是重做 Core 人格系统，也不要求将插件的人格编辑、草稿或页面搬进 Core。

- [ ] 明确插件人格为插件主记录，Core 仅保存需要参与其 Agent/Recall 规则的已发布镜像；插件 Revision 与 Core Revision 分别记录。
- [ ] 冻结完整人格内容到 Core 现有内容结构的合法映射、大小限制、Hash、CAS 和回读语义，复用现有读取/发布/历史/回滚方法。
- [ ] 提供插件可配置的最小管理授权说明与例子。普通 application Token 当前不能发布人格；不能要求插件伪造 admin，也不能把 Console 运营密钥当作 `/v1` Bearer。
- [ ] 明确多人格与 Agent 的初始化/绑定路径：可先消费预配置 Agent；若必须由插件动态创建，需要受权公共能力。当前 SDK 没有通用 Agent 创建方法，不能让插件通过私有 ProvisioningService 实现。
- [ ] 明确外部改动冲突、镜像失败、回滚、Core 自主演进锁定、来源失效和旧 Recall 重验行为；不用关闭 Core Ready/Policy 来绕过接缝。

**验收：** 插件侧模拟多个已发布人格，使用授权公共方法同步、读取、并发冲突和回滚；普通应用凭据的越权发布失败。插件本身的人格编辑与使用在 Core 不可用时仍可独立进行，依赖精确镜像版本的业务明确暂停。

### G-09 双入口契约与依赖消费矩阵

- [ ] 对同一业务请求运行 Embedded 和 SDK→HTTP 两条真实路径，复用公开 DTO/领域规则，覆盖 Scope、幂等、修订、遗忘、权限及错误状态。
- [ ] 能力声明反映已配置、已授权和可支持的范围；瞬时故障通过就绪/降级表达。逐方法声明支持程度，不因接口占位就报可用。
- [ ] 分别管理 Core 包、SDK 包、API 和 Schema 版本；冻结可消费的版本组合、方法签名、错误及弃用窗口。
- [ ] 验证内嵌依赖、服务依赖、SDK-only 的干净安装；测试脱离源码路径，必要资源在 wheel/sdist 中持续可用。
- [ ] 确认 Python/SQLite 的目标宿主兼容范围，提供实际运行库版本诊断；不能把 `--allow-local-sqlite` 开发例外当成正式支持方案。

**验收：** 一份可复现的双入口消费报告、安装清单和产物摘要。真实模型/性能结果与确定性功能测试分别记账，不能以 SDK 方法存在代替实际链路。

## 6. P2：按需管理与发布前验证

### G-10 管理与诊断能力

- [ ] 按插件实际展示需求消费 W07 的队列/索引/Provider 状态、耗时、调用与预算信息；公共错误能关联服务端日志，但不泄露私有对象和凭据。
- [ ] 需要时消费 W10 的保留/Hold、W11 的业务导出、W12 的手动导入，以及 W13/W14 的受权设置/运维能力；逐项说明公开传输、权限和客户端支持。
- [ ] 如果需要程序化管理而独立 SDK 未覆盖，先冻结受权管理方法或独立传输边界；不能调用私有 `_request_json`，也不能自动给普通 SDK 全部 Console 权限。

**验收：** 只为实际要启用的页面操作建立真实链路及错误场景。插件配置、模块开关、人格编辑和插件日志由插件实现，不等待 Core Console 全部完成。迁移功能未支持时明确禁用，不扫描或上传旧私有数据库补洞。

### G-11 正式运行与发布证据

- [ ] W16：满足真实 Python/SQLite 条件，验证服务/Worker 启停及运行配置；Embedded 另补宿主进程的资源和生命周期证据。
- [ ] W17：按 Core 已有发布标准完成权限、凭据、供应链与隔离验证；不新增无关 IAM 项目。
- [ ] W18/W19：在声明规模下完成容量、长稳、故障恢复与升级回退；已确认数据、删除账本和撤销权限不因恢复复活。
- [ ] W15/W20：冻结产物/契约/报告与兼容矩阵，提供安装消费证据；未实际发布的版本不写成已能从注册表安装。

**验收：** Core 自己的正式发布门禁与插件消费报告分别通过。完整 Core Console 发布、真实 AstrBot E2E 和进程内公共 API 是不同交付，任何一项不能代替其余项。

## 7. 建议交接顺序与最小交付

1. **先处理 G-01～G-03 的范围决策和公共契约。** 不必等全部 W01～W20 结束才讨论；当前队列不会自动产生内嵌 API。
2. **复用 W01，推进 W05/W06。** 解决真实检索和提炼的生产接线，不重新实现已存在的 Graph/Vector 路由。
3. **独立推进 SDK、人格接入与轻量化验证。** 优先补影响插件模块热停、完整人格管理和默认成本的部分。
4. **完成 G-09 双入口安装消费。** 至少交付：本地无端口闭环、远程独立 SDK 闭环、公开 Provider 例子、资源/错误说明、兼容矩阵及真实测试结果。
5. **按功能启用管理能力，按发布节点执行生产验收。** 插件 Pages/配置/日志/人格编辑与已支持的 Remote 能力可以继续开发，不等待所有外部工作结束。

请 Core 项目对每项回填：`接受/采用现有能力/需调整/暂缓`、负责人、工作包、接口/ADR、目标版本、验收命令与实际结果。需要改变 v4 产品要求时先反馈，不能自行改成 localhost 服务、合并 SDK 分发或要求插件调用私有对象。

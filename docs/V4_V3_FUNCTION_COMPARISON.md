# v4dev 与 v3 功能对照

核查日期：2026-09-08。

**当前 v4dev 已建立双模式、集中配置、完整人格和统一记忆接入，但尚未覆盖 v3 的全部陪伴功能，不能作为 v3 的无损替代版本。**

## 1. 比较范围与证据

- v3：本仓库 `master`，提交 `b752ffbf1ccaab35bf6708015be5dc5405643775`，`metadata.yaml` 版本 `v3.2.0`。对照实际代码，同时参考 README；不把 README 声明当成此次运行验收结果。
- v4：`dev.4` 当前工作区，版本 `v4.0.0-dev.1`。代码尚未提交，因此不能只用分支 HEAD `801ae9d` 复现本表。
- “已实现”表示当前存在实际入口和处理逻辑；具体已执行测试范围见 [实施与验收报告](V4_IMPLEMENTATION_REPORT.md)。不等于真实 AstrBot、全部平台和模型质量已经通过验收。
- Core 接缝结论对应 [依赖快照](DEPENDENCY_SNAPSHOT.json)；不宣称已经重新验收其他版本或之后的 Core 修改。
- 本次只核查代码并整理文档，没有运行 v3/v4 的同负载质量或性能对照，也没有修改插件业务代码或 Core。

状态说明：**已实现**、**部分覆盖**、**未实现**、**外部阻塞**。改为 Core 承担某项职责，只能证明职责调整，不能自动证明原用户功能已完整恢复。

| 记忆使用反馈 | 检索访问等内部统计 | 报告 Core 返回、宿主选择、模型可见的候选 ID | **已实现**；可见不等于模型在答案中实际使用，更不等于消息送达 |

## 6. 使用判断与后续优先级

当前可用于验证：双模式接入、集中配置、模块热启停、完整人格、显式记忆与纠正遗忘、基础提醒。继续依赖 v3 的群聊自然陪伴、自动记忆沉淀、黑话学习或完整数据管理时，当前 v4dev 还不能直接替换。

建议按功能闭环补齐，以下是后续建议，不是本次已经实施的内容：

1. **先补基础记忆闭环：** Core 明确解决异步认知 Scope 接缝后，插件接入真实提炼 Provider；验证聊天观察→事实→召回，以及助手实际输出的记录规则。只定义接口不等于闭环通过。
2. **再补主要陪伴体验：** 在现有 Task/Focus 上增加简化的群聊插话与事件跟进；复用统一上下文、预算和发送，不恢复独立长期事实库。
3. **完善删除与备份恢复：** 明确 Claim/来源观察/宿主历史的不同删除范围，再提供用户/会话管理和插件控制数据＋Core 数据的一致备份恢复。
4. **做检索与宿主验收：** 同模型同数据回放 v3/v4 的中文、时间、纠正、无答案场景；完成真实 AstrBot 群聊/私聊、多轮人格采用、资源与长稳验证。
5. **按需要补高级功能：** 表达/黑话、人格学习的自动采样与独立审查、图片缓存、图谱可视化、旧命令兼容。它们并非低成本记忆首版全部必需，但必须明确取舍。

外部条件仍需注意：当前已验证的 Core 快照本地使用 Unix 锁和 SQLite allowlist；本地每个“会话/人格”占一个注册组合，总上限 128；远程需预配置身份与 Agent/Space。详见 [Core 待补项](CORE_V4_FOLLOWUP.md)。
